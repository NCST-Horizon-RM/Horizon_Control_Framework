# 平移、旋转功率分配

## 作用

本模块把同一底盘上每个驱动电机的电流请求拆成平移和旋转两类运动分量，并为整组电机求两个公共保留比例 `t`、`r`：

```text
limited_cmd[i] = t × translation_cmd[i] + r × rotation_cmd[i]
```

`t`、`r` 的范围均为 `0~1`。两类比例对所有轮共用，不逐轮独立截断，因此可以保持底盘运动分量的整体方向。

## 电机功率模型

每个电机使用本周期实际转速和候选合成电流预测输入功率：

```text
ω = speed_rpm × 2π / 60
I = current_cmd × current_convert

P = k1 × ω × I + k2 × I² + k3 × ω² + k4
```

`speed_rpm` 的单位是 rpm，`current_cmd` 和 `max_cmd` 的单位是电调 raw，`I` 的单位是 A，`P` 的单位是 W。

当前模型使用带符号净功率：

```c
total_power += motor_power;
```

不执行 `max(motor_power, 0)`。因此制动电机的负功率可能抵扣其他电机功率。该模型是控制分配的近似模型，低速、静摩擦、换向和母线电压变化会造成较大误差，需要通过实车数据标定。

当前 M3508 参数为：

```text
k1 = 1.5756e-2
k2 = 1.94e-1
k3 = 1.9202e-5
k4 = 1.15 W
current_convert = 20 / 16384 A/raw
```

## 数据结构

每个 `Power_Motion_Node_t` 对应一个真实电机：

```c
typedef struct {
    Power_Node_t motor;
    float translation_cmd;
    float rotation_cmd;
    float max_cmd;
} Power_Motion_Node_t;
```

使用要求：

1. `motor.state` 指向该电机独立的 `Motor_Power_State_t`；
2. `motor.model` 指向有效的电机模型；
3. `speed_rpm` 是本周期实际测得的转速；
4. 两类电流和 `max_cmd` 使用相同的 raw 单位；
5. 不同节点不能复用同一个状态对象；
6. `max_cmd` 限制的是合成电流的绝对值。

分配结果 `Power_Motion_Result_t` 包含：

```text
translation_scale  平移保留比例 t
rotation_scale     旋转保留比例 r
requested_power    t=r=1 时的预测功率
allocated_power    最终 t、r 下的预测功率
status             求解状态
```

最终电流写入：

```c
nodes[i].motor.state->limited_cmd
```

## 二维求解流程

### 1. 输入校验

检查节点数组、模型指针、状态指针、转速、电流、模型系数和功率上限是否有限且合法，同时检查状态对象是否重复。

非法输入返回 `POWER_MOTION_INVALID_INPUT`，可访问的 `limited_cmd` 会先清零。

### 2. 构造功率二次函数

把所有电机的功率展开为关于两个比例的二次函数：

```text
P(t,r) = A·t² + B·t·r + C·r² + D·t + E·r + F
```

其中 `A~F` 由每个电机的模型参数、实际转速、平移 raw 电流和旋转 raw 电流累加得到。`B` 保留了平移与旋转的交叉影响。

### 3. 构造电流可行区间

对固定的 `t`，每个电机必须满足：

```text
|t·translation_cmd[i] + r·rotation_cmd[i]| ≤ max_cmd[i]
```

将所有节点给出的 `r` 区间求交，并与 `0~1` 相交，得到当前 `t` 下的旋转比例可行区间。

### 4. 寻找功率谷值

定义固定 `t` 时的最小功率：

```text
F(t) = min P(t,r)
```

先在当前 `r` 区间内解析求出功率最低点，再对 `F(t)` 做固定次数的三分搜索，得到功率谷值 `t_m`。

如果谷值仍高于 `allowed_limit`，则没有满足功率约束的候选组合。

### 5. 求功率可行带

以 `t_m` 为中心，在左右两侧分别二分，求出满足：

```text
F(t) ≤ allowed_limit
```

的平移比例范围 `[fa, fb]`。不能简单假设功率随比例单调增加，因为带符号模型在制动时可能先降后升。

### 6. 选择运动目标最优点

在功率可行带内，固定 `t` 求出满足功率约束的最优 `r`，然后最小化运动误差：

```text
J(t,r) = w_tt·(1-t)²
       + 2·w_tr·(1-t)·(1-r)
       + w_rr·(1-r)²
```

使用黄金分割搜索 `J(t,r)` 的最小值。权重由两类原始电流的大小归一化得到，并保留两类电流的交叉项。

### 7. 复核与输出

求解结果重新使用完整功率函数和逐轮电流约束复核。若由于浮点舍入略微越界，则沿比例向零方向进行有限次 `nextafterf()` 回退。

复核通过后，写入每个节点的 `limited_cmd`。如果复核失败，返回 `POWER_MOTION_NO_FEASIBLE_CANDIDATE` 并输出零电流。

## 运动模式优先级

`Power_Ctrl_Allocate_Motion_Optimal()` 使用平移、旋转等权的二维优化。

`Power_Ctrl_Allocate_Motion_With_Priority()` 仍使用同一求解器，只改变目标函数权重：

| 优先级 | 权重 | 底盘模式 |
| --- | --- | --- |
| `POWER_PRIORITY_ROTATION` | 旋转误差权重提高 32 倍 | 底盘跟随 |
| `POWER_PRIORITY_TRANSLATION` | 平移误差权重提高 32 倍 | 旋转/小陀螺 |

这是软优先级，不会突破功率和电流硬约束，也不会固定某个比例为 `1`。功率不足时，跟随模式倾向增大 `r`、降低 `t`；旋转模式倾向增大 `t`、降低 `r`。

## 底盘接入

任务层先将底盘 PID 输出作为目标加速度，分别生成两类轮电流：

```c
Chassis_Force(cfg, ax, ay, 0.0f, fb, &translation_command);
Chassis_Force(cfg, 0.0f, 0.0f, aw,  fb, &rotation_command);
```

再为四个节点填写：

```c
m_states[i].speed_rpm = c_motor->DJI_3508_Chassis[i].Speed_now;
motion_nodes[i].translation_cmd = translation_command.wheel_torque_raw[i];
motion_nodes[i].rotation_cmd    = rotation_command.wheel_torque_raw[i];
motion_nodes[i].max_cmd         = 16000.0f;
```

根据裁判系统、缓冲能量和超级电容策略得到本周期 `final_limit`，调用：

```c
Power_Ctrl_Allocate_Motion_With_Priority(
    final_limit, motion_nodes, 4, power_priority, &result);
```

只有 `POWER_MOTION_OK` 或 `POWER_MOTION_LIMITED` 才发送 `limited_cmd`，其他状态发送零电流。

## 状态码

| 状态 | 含义 | 调用方处理 |
| --- | --- | --- |
| `POWER_MOTION_OK` | 完整请求满足功率和电流约束 | 发送结果 |
| `POWER_MOTION_LIMITED` | 找到满足约束的缩放组合 | 发送结果 |
| `POWER_MOTION_NO_FEASIBLE_CANDIDATE` | 未找到可行组合 | 发送零电流 |
| `POWER_MOTION_INVALID_INPUT` | 输入非法 | 检查配置并发送零电流 |
